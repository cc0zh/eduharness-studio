# 分阶段路线图（M0–M4）

总原则：**越轻量越好**（不做登录注册、外部数据库、TTS、自由手绘或重运维），每个里程碑以真实端到端 E2E 验收为核心。

## M0（已完成）：Day-1 骨架与门禁

- 三层仓库结构（`packages/engine`、`apps/server`、`apps/web`）与基础纯引擎契约。
- 文档骨架与防堆放 Lint、三层导入边界 Lint、`npm run check` 与 CI。
- 一键 `npm run dev` 并行拉起前后端最小页面与 M0 E2E 连通冒烟。

## M1（已完成）：零密钥离线端到端闭环（详细契约与切片见 [M1 详细规格书](../archive/m1-spec.md)）

- 精选示范课一键直达 + 2–3 步轻调研生成动态两层课程蓝图（后续课节懒生成）。
- 分栏白板按拍 SSE 演播（板书、荧光高亮/圈画、SVG 示意图、底部字幕、`ask` 停顿、动态要点进度条）。
- 左侧可折叠课堂记录栏、暂停/单拍/中途打断截断与 SQLite 刷新恢复。
- `Agent X-Ray` 工程抽屉 + 离线 6 维质检 + `#n` 证据回绑高亮，以及 Playwright 浏览器 E2E 测试。

## M1.5（已完成 · 零模型费用）：前端视觉重构与配图样板（详细边界与切片见 [M1.5 详细规格书](../archive/m1.5-spec.md)）

- 在严守两层结构、按拍演播、`ask`/打断焦点互斥与纯净学生态红线的前提下，升级中文排版、画布质感、去套框分栏白板与 `Agent X-Ray` 抽屉视觉。
- 在现有 2 节示范课上对比 2–3 种白板配图效果样板（如统一画风静态 SVG / 轻量动效交互卡 / 确定性结构模板），眼见为实后拍板 M2 的 `graph` 生成机制。

## M2（已验收）：真实模型与完整课堂闭环（[归档规格](../archive/m2-spec.md) · [验收证据](../status.md#m2-验收证据)）

- **统一模型边界**：仅在 `packages/engine/src/models.ts` 直接复用 `@earendil-works/pi-ai` 成熟供应商注册表与鉴权体系，支持 `.env`（含 `HTTPS_PROXY` 代理）与顶栏内存态临时 BYOK 弹窗（密钥绝不落库或写日志）；无 Key 时自动回落零密钥离线模式。
- **完整真课堂闭环**：经预算授权跑通自由主题轻调研、动态蓝图、第 2 节懒解锁、白板演播、作答与打断续讲、刷新恢复。白板配图用静态铜版风 SVG，经消毒，不能生成时退回文字板书。
- **教师引擎执行架构**：认知规划型受控单回合闭环（显式诊断 + 卡壳动态插补课要点 + 诊断型选项 `ask` 与敷衍柔性降级 + 状态机硬护栏自纠偏，重点保 `verify` 过关门禁，吸取 `eduharness` 阶段 3 教训绝不写死生硬交权话术，不做多轮自由 UI Tool-Calling）+ 轻量安全数学工具 `calc_verify`（零 `eval`、零联网，X-Ray 展示诊断/拦截/耗时）+ 统一按拍事件流抽象；先打穿单堂真课并尽早授权试学，若实测首拍等待偏慢再借 `pi-ai` 平滑升级流式逐拍解析（前端零改动）。
- **契约预留与 X-Ray 边界**：课节/课程契约预留可选 `basis`（课前依据与来源）槽位供 M4 扩展；`Agent X-Ray` 在 M2 保持实时工程追踪与离线 6 维快检，不在本仓重复维护真 6 维裁判 prompt（真裁判归口 M3）。

## M3（已收官）：`eduharness-ts` 双项目真评测闭环与收官（[归档规格](../archive/m3-spec.md) · [验收证据](../status.md#m3-验收证据)）

- 以同栈 TypeScript 仓库 `eduharness-ts`（完整 `e1-binary-v3` 6 维 19 题尺子，99/99 黄金对拍 0 偏差）为唯一评测底座；老 JS 版 `eduharness` 保持只读归档。
- `eduharness-ts` 补齐极轻 `--judge-only` 外部公开对话评分入口（兼完成 Phase 4 授权真机验证）；`studio` 冻结前端 UI 与既有业务功能，交付纯引擎 `EvidenceMessage[]` 投影与只读 SQLite 导出 CLI（`npm run export:judge`）。
- 完成 4 场景离线预演与守卫加固，经预算授权完成首轮真机 `live-02`（Studio 19/114 POST）与 `eduharness-ts --judge-only --mode real`（12/72 次、0 重试、`--verify-run` 通过与 Chrome 离线 HTML 核验），并将两项已知内容与脚本边界诚实入档、统一收口 [README](../../README.md)。
